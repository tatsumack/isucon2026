## ボトルネック上位 (スコアへの効果が大きい順)

### 1. 最後の期間に asia の「その他」の API が詰まる

- 根拠
  - 優先制御の「その他」の平均の待ちは、ピークで 2.2〜3.4s
  - asia で投稿しなかった 578人は、最後の期間に友達申請・検索・Memories・`/api/me` で 2〜4秒ずつ待っていた
- 原因箇所: `go/priority.go` の `splitPriorityMiddleware`。「その他」は12枠
  - 枠に入るまでの待ちが1秒を超えると共通の追加枠 (4) を待つので、合わせても16並列までしか動かない
- 対策案
  - asia1 の CPU を空けて、枠が早く空くようにする (2〜4)
  - 「その他」の枠を増やした場合に asia の4日目の完了率が下がらないかを、ベンチで確かめる
- 期待効果: 大。最後の期間の未投稿 (約400人 × 20点) が減る
- リスク: 投稿の経路の枠を減らすと、4日目の完了率が下がり、5日目の人数が増えなくなる (#24645 の状態に戻る)

### 2. 画像の署名を asia1 で計算している (10.1%)

- 根拠: `computeImageSignature` 4.89s。そのうち `issueImageSignature` からが 3.99s で、ほとんどが sha256 (asia1 には SHA-NI が無い)
- 対策案: #64 のように、europe1 / america1 に計算を回す範囲を広げる
- 期待効果: 中

### 3. export (8.3%) とプロフィール画像 (6.2%)

- 根拠
  - export: 106回 (#24645 から -45)、平均 1.58s
  - プロフィール画像: 673回、平均 2.63s、4xx が141件
- 対策案: プロフィール画像の不正な画像を、本体を読み切る前に 400 で返す。export の画像の読み込みの内訳は、まだ見ていない
- 期待効果: 小〜中

### 4. asia1 のディスクの読み込み (1,739MB)

- 根拠: 張り付く区間の wa は 5〜32%。`GET /api/images` は 6,928回、平均 1.073s (うち優先制御の待ちを含む)
- 対策案: 読み込んだ画像の出どころ (初期データ / 新しい投稿) を数え、多い方に手を打つ (#24645 の報告と同じ)
- 期待効果: 中
