## 概況

- **転送された europe / america の API は速くならなかった** (#20097 → #21405)
  - europe1 feeds 0.573s → 0.566s、posting-window/current 0.613s → 0.542s、posts 0.864s → 1.058s
  - america1 feeds 0.602s → 0.628s、posting-window/current 0.619s → 0.641s
- asia1 の負荷の山 (t=45〜90秒): us 35.2 / sy 37.4 / idle 15.9 / wa 11.6。europe1 / america1 は idle 約92%
- asia1 の処理量は増えた: 投稿 1949 → 2636回、feeds 6394 → 7788回、posting-window/current 2711 → 3840回
  - asia1 の CPU を使っているのは、上限の対象外の「投稿期間の確認 → 投稿 → フィード」の流れ。heavy の3つを抑えても、転送された API の待ちは減らなかった

## 評価

- 段階1 (heavy) は、狙った「europe / america の転送された API を速くする」効果が出ていない
- 上限 8 では、負荷の山で枠が常に埋まり、1秒で上限を無視する安全策が働いて、上限として機能していない
- スコアの +9.7% は asia の人数の増加によるもので、#57 (画像アップロードのコピー削減) で asia1 の CPU が空いた効果と考えられる (推測。#57 単体のベンチは見ていない)

## 次に試すこと

- `ISUREAL_PRIORITY_SCOPE=all` (段階2) にして、asia の「投稿期間の確認 → 投稿 → フィード」も上限の対象にする。asia1 の CPU を使っているのはこの流れなので、ここを抑えないと転送された API に CPU が回らない
- 上限は、対象が増えるので 8 より大きくする (例: 32)。`gave_up` が多ければ上げ、`waited` が少なければ下げる
- EOF のエラーが続くかを見る
