- **エクスポートは速くなっていない。** asia1 で 191回 / 平均 0.823s → 176回 / 平均 0.885s
- **asia1 の CPU は同じ。** idle の平均 62.5% → 63.1%、idle 5% 未満の秒数 26 → 19。`Syscall6` は 24.9% → 24.5%

## ボトルネック上位

### 1. エクスポートの画像キャッシュが当たらない

- 根拠: `readImageFile` 2.08s (エクスポートから)。#35726 のファイル I/O 約2.2s とほぼ同じ
- 原因箇所: `go/image_export.go` の `exportImageCache` (256MB、古いものから追い出す)
- 推測される理由 (未確認): #33924 の「同じユーザーの2回目以降が 233回中 144回」は、エクスポートの間隔の件数を数えたもので、同じ画像の読み直しの割合ではなかった。もしくは、1回で約2MB × 176回 ≈ 350MB を入れるので、256MB を超えて先に追い出された
- 対策案: 取り下げる (推奨)。続けるなら、ヒット率をログに出して確かめてから上限を見直す
- リスク: なし (元に戻すだけ)

### 2. エクスポート全体が asia1 の CPU の 10% を使う

- 根拠: `exportPostsHandler` cum 5.07s (10.2%)。うち画像の読み込み 2.08s、ZIP への書き込み 1.08s
- 対策案: ZIP の組み立てを毎回やめる (ユーザーごとのエクスポート結果のキャッシュ。投稿の作成・削除・キャプション変更で無効化する) など。1回20点の活動なので、壊すと FAIL になることに注意
- 期待効果: 中。asia1 の CPU を最大で約10%空ける
