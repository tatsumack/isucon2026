## ボトルネック上位

### 1. ユーザー検索がDB時間1位

- 根拠: 3,194回、平均10.88ms、合計34.8s、DB時間17.0%。#28870 は3,467回、平均7.36ms、合計25.5s、14.6%。
- 原因箇所: `go/user_read_api.go:80`。部分一致2列、ブロック関係の `NOT EXISTS`、`username,id` 順のページングを同時に行う。
- 対策案: 実際の検索語で `EXPLAIN (ANALYZE, BUFFERS)` を取り、GIN利用後のソート・ブロック判定・ページングのどこが増えたかを確認する。短い検索語と長い検索語を分けて確認する。
- 期待効果: 大。現在のDB時間1位。
- リスク: 検索順序、51件上限、ブロック除外の仕様を維持する必要がある。

### 2. 投稿署名の遠隔計算が22.3%タイムアウト

- 根拠: 投稿2,790件中、遠隔結果を利用できたのは2,167件 (77.7%)、623件 (22.3%) は150msで打ち切ってasia1でも計算。europe1 / america1 では `computeImageSignature` がそれぞれ5.51s / 4.89s cumulative。asia1 のSHA flat CPUは40%減ったが、asia1の投稿平均は174%増えた。
- 原因箇所: `go/post_api.go:255`, `go/post_api.go:263`, `go/post_api.go:295`。DBコミット後、遠隔結果を最大150ms待つ。高負荷時は遠隔HTTP自体にもdeadline超過が出る。
- 対策案: まず待ち時間を延ばすのではなく、遠隔処理のキュー・同時実行数とHTTPタイムアウトを計測する。投稿レスポンスを遅くしないことを優先するなら、待機上限を50ms付近へ戻しつつ遠隔計算を次回キャッシュ用に完走させる比較ベンチを行う。
- 期待効果: 大。投稿は得点に直結し、P95が約0.75秒悪化している。
- リスク: 待ち時間を短くするとasia1のCPU削減量が減る。長くすると投稿期間内の完了率を落とす可能性がある。

### 3. セッション検索が大量かつ遅くなった

- 根拠: 51,318回、平均0.41ms、合計20.9s、DB時間10.2%。#28870 は53,611回、平均0.03ms、合計1.55s、0.9%。件数は減っているのに平均が約14倍。
- 原因箇所: `go/session.go:50`。ほぼ全認証リクエストで `login_sessions` と `users` をJOINする。
- 対策案: `EXPLAIN (ANALYZE, BUFFERS)` と `pg_stat_user_indexes` で `token_hash` のインデックス利用、キャッシュヒット、テーブル膨張を確認する。今回固有のDB負荷による二次的悪化かを再ベンチで切り分ける。
- 期待効果: 大。呼び出し回数が5万回超で、わずかな改善が効く。
- リスク: セッション失効、ユーザー停止、region変更の即時反映を壊すキャッシュは不可。

### 4. `image_owners` の初回取り込みが初期化を14.6秒延ばす

- 根拠: 1回、1,831,312行、14.55s、DB時間7.1%。`POST /api/initialize` は17.15s。
- 原因箇所: `sql/005-image-owners.sql:13`。テーブルが空の場合に全 `image_objects` パーティションから一括コピーする。
- 対策案: 初期データ生成時に `image_owners` も直接ロードする、または初回構築をデプロイ時に済ませる。ベンチの初期化要件上、前回データを安全に再利用できるか確認する。
- 期待効果: 中。計測されたDB時間は大きいが、通常APIの定常ボトルネックではない。
- リスク: 初期化後の所有者・media typeとの整合性が必須。古い行が残る設計は不可。

### 5. 閲覧者コンテキスト取得がDB時間3位

- 根拠: 15,764回、平均1.07ms、合計16.9s、DB時間8.3%。#28870 は平均1.27ms、合計20.0sであり、単体では改善しているが依然上位。
- 原因箇所: `go/post.go:117`。本人、当日投稿、ブロック、友達、友達の友達を1クエリで集約する。
- 対策案: `EXPLAIN (ANALYZE, BUFFERS)` で友達の友達の `UNION ALL` と `json_agg` の比率を確認する。結果の再利用範囲があるなら、リクエスト内で重複取得を避ける。
- 期待効果: 中。平均は小さいが1.5万回呼ばれる。
- リスク: 友達・ブロック更新直後の可視性と、投稿済み判定の整合性。
